# TRACE 팀 스탠드업

팀원 세 명(A·B·C)이 각자 Claude로 개발합니다. 이 스킬은 모두가 같은 기록을 보고 이어서 일하도록, 세션 시작과 끝에 GAKDO/docs의 기록을 읽고 고칩니다.

## 원본

GAKDO/docs(https://github.com/GAKDO/docs)의 `team/`이 원본입니다.

- `team/conventions.md`: 코드 컨벤션
- `team/board.md`: 기능별 상태 = 남은 작업
- `team/standup/YYYY-MM-DD.md`: 날짜별 기록, 사람마다 자기 칸
- `team/standup/TEMPLATE.md`: 새 날짜 파일의 틀

역할: **A** 서버 6개·인프라·집 PC, **B** 부스·진단 에이전트·학습 데이터, **C** 화면. 사용자가 말한 역할을 쓰고, 말하지 않았으면 이 레포 `CLAUDE.md`의 담당을 기본값으로 삼되 한 번 확인합니다.

## docs 가져오기

1. 세션에 GAKDO/docs가 함께 연결돼 있으면 그 폴더를 씁니다.
2. 아니면 이 레포 옆의 `../docs`를 찾고, 없으면 `git clone --depth 30 https://github.com/GAKDO/docs.git "${TMPDIR:-/tmp}/trace-docs"`로 받습니다. 이미 있으면 `git pull --rebase`.
3. 받지 못하면(권한 오류) 멈추고 사용자에게 "세션에 GAKDO/docs 레포를 함께 연결해 주세요"라고 알립니다. 기록을 지어내지 않습니다.

날짜는 한국 시간(Asia/Seoul) 기준입니다: `TZ=Asia/Seoul date +%F`.

## start: 세션을 시작할 때

1. 오늘 파일이 없으면 `TEMPLATE.md`를 복사해 만들고 날짜를 채웁니다.
2. `board.md`, 어제와 오늘 스탠드업을 읽습니다. 이 세션에서 처음이면 `conventions.md`도 읽습니다.
3. 사용자에게 5줄 이내로 알립니다.
    - 내 역할의 `진행`·`대기` 기능을 마감 순으로
    - 어제 "오늘 할 일" 중 끝내지 못한 것
    - 나와 관련된 `막힘`, 계약 변경, "공유" 칸의 새 내용
4. 오늘 할 일을 사용자와 정해 내 칸의 "오늘 할 일"에 적습니다. 시작하는 기능은 `board.md`에서 상태를 `진행`으로 바꾸고 브랜치를 적습니다.
5. 아래 규칙대로 커밋·푸시합니다.

## end: 세션을 끝내기 전

1. 이 레포에서 오늘 한 일을 확인합니다: `git log --since="today 00:00" --oneline --all`, 이 세션에서 연 PR.
2. 내 칸을 고칩니다. "한 일"은 사실만(PR·커밋 링크), "남은 것"과 "막힌 것"은 한 줄씩, "다음에 할 일"은 다음 세션이 바로 시작할 수 있게 한 줄로.
3. `board.md`의 내 기능 행을 고칩니다: 상태(`진행` → `리뷰` → `완료`, 막히면 `막힘`과 이유), 브랜치·PR, 갱신일.
4. 커밋·푸시합니다.

## 상태만 물을 때

"팀 상황", "남은 작업", "B는 뭐 해?" 같은 질문에는 `board.md`와 오늘 파일을 읽어 표로 답하고, 아무것도 쓰지 않습니다.

## 쓰기 규칙

- **내 칸과 내 기능 행만** 고칩니다. 다른 사람의 글은 지우거나 고치지 않습니다.
- 한 줄에 하나, 짧게. 비밀번호·토큰·개인정보·학번은 쓰지 않습니다.
- 계약 변경이나 팀 결정이 생기면 오늘 파일의 "공유" 칸에 한 줄 남깁니다.
- 커밋 메시지: `docs(standup): 11/02 B 시작`, `docs(standup): 11/02 B 마무리`, `docs(board): BO1 리뷰`.
- 푸시 전에 `git pull --rebase`. 거절되면 다시 받아 최대 3번 재시도하고, 그래도 안 되면 사용자에게 알립니다.
- 다른 사람과 같은 파일을 동시에 고쳐 충돌하면, 다른 사람의 줄은 원격 내용을 그대로 두고 내 칸·내 행의 변경만 다시 적용한 뒤 `git rebase --continue` 합니다. 다른 사람의 줄을 내 것으로 덮어쓰지 않습니다.
