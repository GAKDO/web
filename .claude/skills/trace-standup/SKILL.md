# TRACE 팀 스탠드업

팀원 세 명(A·B·C)이 각자 Claude로 개발합니다. 이 스킬은 모두가 같은 기록을 보고 이어서 일하도록, 세션 시작과 끝에 GAKDO/docs의 기록과 구현현황 시트를 읽고 고칩니다.

## 원본

GAKDO/docs(https://github.com/GAKDO/docs)의 `team/`이 원본입니다.

- `team/conventions.md`: 코드 컨벤션
- `team/board.md`: 기능별 상태 = 남은 작업
- `team/standup/YYYY-MM-DD.md`: 날짜별 기록, 사람마다 자기 칸
- `team/standup/TEMPLATE.md`: 새 날짜 파일의 틀

구현현황 시트(Google 시트 "TRACE 요구사항 구현현황")는 기능 109개의 작동 여부와 서버별·담당별 구현율을 보여 주는 요약판입니다. 작업 상태의 원본은 `board.md`이고, 시트는 완료된 기능을 체크하는 곳입니다.

역할: **A** 서버 6개·인프라·집 PC, **B** 부스·진단 에이전트·학습 데이터, **C** 화면. 사용자가 말한 역할을 쓰고, 말하지 않았으면 이 레포 `CLAUDE.md`의 담당을 기본값으로 삼되 한 번 확인합니다.

## docs 가져오기

1. 세션에 GAKDO/docs가 함께 연결돼 있으면 그 폴더를 씁니다.
2. 아니면 이 레포 옆의 `../docs`를 찾고, 없으면 `git clone --depth 30 https://github.com/GAKDO/docs.git "${TMPDIR:-/tmp}/trace-docs"`로 받습니다. 이미 있으면 `git pull --rebase`.
3. 받지 못하면(권한 오류) 멈추고 사용자에게 "세션에 GAKDO/docs 레포를 함께 연결해 주세요"라고 알립니다. 기록을 지어내지 않습니다.

날짜는 한국 시간(Asia/Seoul) 기준입니다: `TZ=Asia/Seoul date +%F`.

## start: 세션을 시작할 때

1. 오늘 파일이 없으면 `TEMPLATE.md`를 복사해 만들고 날짜를 채웁니다.
2. `board.md`, 어제와 오늘 스탠드업을 읽습니다. 이 세션에서 처음이면 `conventions.md`도 읽습니다.
3. 구현현황 시트를 읽을 수 있으면(아래 "구현현황 시트") 요약에서 총 구현율과 내 담당 구현율을 읽습니다.
4. 사용자에게 5줄 이내로 알립니다.
    - 내 역할의 `진행`·`대기` 기능을 마감 순으로
    - 어제 "오늘 할 일" 중 끝내지 못한 것
    - 나와 관련된 `막힘`, 계약 변경, "공유" 칸의 새 내용
    - 구현율 한 줄: `총 6.42% · 내 담당(A) 9.86% (7/71)` (시트를 못 읽으면 생략)
5. 오늘 할 일을 사용자와 정해 내 칸의 "오늘 할 일"에 적습니다. 시작하는 기능은 `board.md`에서 상태를 `진행`으로 바꾸고 브랜치를 적습니다.
6. 아래 규칙대로 커밋·푸시합니다.

## end: 세션을 끝내기 전

1. 이 레포에서 오늘 한 일을 확인합니다: `git log --since="today 00:00" --oneline --all`, 이 세션에서 연 PR.
2. 내 칸을 고칩니다. "한 일"은 사실만(PR·커밋 링크), "남은 것"과 "막힌 것"은 한 줄씩, "다음에 할 일"은 다음 세션이 바로 시작할 수 있게 한 줄로.
3. `board.md`의 내 기능 행을 고칩니다: 상태(`진행` → `리뷰` → `완료`, 막히면 `막힘`과 이유), 브랜치·PR, 갱신일.
4. 오늘 실제로 동작을 확인한 기능이 있으면 구현현황 시트에서 그 행을 찾아, 체크할 행 목록을 사용자에게 보여 주고 확인받은 뒤 체크합니다(아래 "구현현황 시트").
5. 커밋·푸시합니다.

## 상태만 물을 때

"팀 상황", "남은 작업", "구현율", "B는 뭐 해?" 같은 질문에는 `board.md`, 오늘 파일, 시트 요약을 읽어 표로 답하고, 아무것도 쓰지 않습니다.

## 구현현황 시트

Google Drive와 Google Sheets 커넥터가 이 세션에 있을 때만 씁니다. 없으면 이 절을 건너뛰고, end에서 "시트 체크는 직접 해 주세요(커넥터를 연결하면 다음부터 제가 합니다)"라고 한 줄 알립니다.

**찾기.** 시트 주소는 공개 레포에 두지 않습니다. Drive 검색으로 찾습니다: `title = 'TRACE 요구사항 구현현황' and mimeType = 'application/vnd.google-apps.spreadsheet'`. 하나가 아니거나 없으면 사용자에게 팀장이 공유한 링크를 받아 그 ID를 씁니다. 탭 이름은 `구현현황`입니다.

**구조.**

| 위치 | 내용 | Claude가 고치나 |
| --- | --- | --- |
| A열 | 상세 서버. 서버마다 세로로 합친 칸이라 읽으면 첫 행에만 이름이 있음 | 아니오 |
| B·C열 | 카테고리, 세부 기능 | 행 추가 때만 |
| D열 | 작동 여부 체크박스(TRUE/FALSE) | **예, 내 담당 행만** |
| E열 | 완료율 수식 `=IF(Dn,1,0)` | 아니오 |
| F열 | 비고 | **예, 내 담당 행만, 덧붙이기** |
| G·H열 | 요구사항 ID, 담당(A·B·C) | 행 추가 때만 |
| "구현율" 행 | 서버 묶음 끝의 파란 행, 수식 | 아니오 |
| J3:M17 | 요약(서버별·총·담당별 구현율), 수식 | 아니오 |

**읽기.** 요약은 `get_values`로 `'구현현황'!J3:M17`, 기능 목록은 `'구현현황'!A1:H`를 읽습니다. A열이 빈 행은 위쪽 서버 이름을 이어 받습니다.

**체크.** 오늘 끝낸 기능의 요구사항 ID(`board.md`·`speckit/backlog.md`)와 세부 기능 이름으로 행을 찾습니다. 그중 H열이 내 역할인 행만 고릅니다. "실제로 동작을 확인한 것"만 체크합니다(PR이 머지되고 테스트나 배포 확인을 마친 것). 사용자에게 `행 번호 · 세부 기능 · 근거(PR)`로 보여 주고 확인받은 뒤, `update_values`로 D열에 `TRUE`를 쓰고 F열은 기존 내용 뒤에 ` / 11/03 PR 링크`처럼 덧붙입니다. 쓴 뒤 다시 읽어 요약의 내 담당 구현율이 바뀌었는지 확인합니다.

**되돌리기.** 체크한 기능이 다시 깨지면 사용자와 확인한 뒤 D열을 `FALSE`로 바꾸고 F열에 날짜와 이유를 덧붙입니다.

**행 추가.** 사용자가 요청할 때만 합니다. 해당 서버 묶음 안("구현율" 행 위)에 `insert_dimension`(`inheritFromBefore: true`)으로 한 행을 넣고 B·C·G·H, D열 `FALSE`, E열 `=IF(Dn,1,0)`을 씁니다. 묶음 밖이나 "구현율" 행 아래에는 넣지 않습니다(구현율 계산에서 빠짐).

**하지 않을 것.** 수식·서식·합친 칸·요약은 고치지 않습니다. 다른 사람 담당 행은 체크하지 않습니다. 시트 링크·ID·팀원 이메일을 레포나 docs에 적지 않습니다.

## 쓰기 규칙

- **내 칸과 내 기능 행만** 고칩니다. 다른 사람의 글은 지우거나 고치지 않습니다.
- 한 줄에 하나, 짧게. 비밀번호·토큰·개인정보·학번은 쓰지 않습니다.
- 계약 변경이나 팀 결정이 생기면 오늘 파일의 "공유" 칸에 한 줄 남깁니다.
- 커밋 메시지: `docs(standup): 11/02 B 시작`, `docs(standup): 11/02 B 마무리`, `docs(board): BO1 리뷰`.
- 푸시 전에 `git pull --rebase`. 거절되면 다시 받아 최대 3번 재시도하고, 그래도 안 되면 사용자에게 알립니다.
- 다른 사람과 같은 파일을 동시에 고쳐 충돌하면, 다른 사람의 줄은 원격 내용을 그대로 두고 내 칸·내 행의 변경만 다시 적용한 뒤 `git rebase --continue` 합니다. 다른 사람의 줄을 내 것으로 덮어쓰지 않습니다.
